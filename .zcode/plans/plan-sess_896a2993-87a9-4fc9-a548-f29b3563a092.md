# AI Analysis & Summary — Implementation Plan

A new sidebar analytics area (admin + hiring manager) that auto-generates and saves a Gemini AI analysis for every **concluded shift**, renders it as a data-visualization dashboard (narrative summary, bar chart, pie chart, overall % performance score), and exports a branded per-worker PDF with screenshot evidence and a required "billed to" hiring-manager selection — mirroring the execution-report invoice flow.

**Zero new dependencies**: Gemini via raw `fetch` (same pattern as the existing `avs-frontend` chat route, free-tier `gemini-2.5-flash`), charts hand-rolled in SVG (repo convention), PDF via the already-installed `@react-pdf/renderer`.

## Backend (`workforce-backend`)

**1. New model `src/models/ShiftAnalysis.ts`** — one doc per concluded shift, unique index on `shiftSessionId` (mirrors `MonitoringSession`):
- Identity: `shiftSessionId`, `userId`, `workDate`
- Result: `status` (completed/failed), `source` ("gemini" | "fallback"), `model`, `generatedAt`, `error`
- Scores: `overallScore`, `adherenceScore` (snapshots of the formula-based persisted KPI)
- `metrics` snapshot fed to Gemini: scheduled/worked/break/late/overtime minutes, punctuality/work/activity-adherence scores, attendance status, closure reason, monitoring totals (mouse movements/distance/clicks/scrolls, active-sample %), per-hour activity buckets, capture count, and last captures `[{captureId, capturedAt}]` for PDF evidence
- `narrative`: `{ headline, workerSummary, workSummary, highlights[], concerns[] }`
- `charts`: `{ bar: {title, unit, series[{label,value}]}, pie: {title, unit, segments[{label,value}]} }`

**2. New module `src/modules/analysis/`** (routes/controller/service, mounted at `/api/analysis` in `app.ts`):
- `analysis.service.ts`:
  - `collectShiftMetrics(shiftId)` — joins `ShiftSession` + `ShiftEvent` timeline + `MonitoringSession` (mouse totals, per-hour buckets from `mouseSamples`, captures)
  - `callGemini()` — REST `fetch` to `generativelanguage.googleapis.com/v1beta/models/${GEMINI_MODEL || "gemini-2.5-flash"}:generateContent` with JSON response mode, low temperature, free-tier-friendly in-process queue (sequential + small delay)
  - `generateShiftAnalysis(shiftId, {force})` — validates/clamps Gemini's JSON (charts, narratives); deterministic fallback (template narrative + charts computed from metrics) when the key is missing or the API fails; absent/missed shifts get a deterministic no-Gemini analysis
- Routes (all `protect, requireAdminOrSupervisor`, supervisors scoped to `assignedAgentIds` like existing modules):
  - `GET /overview` — header aggregates · `GET /workers` — workers with concluded shifts · `GET /workers/:userId/shifts` — concluded shifts + analysis status · `GET /shift/:shiftId` — saved analysis · `POST /shift/:shiftId/generate` — generate/regenerate

**3. Auto-generation hooks** (the "concluded shift" moments that already call `persistShiftKpi`):
- `endShift()` in `attendance.service.ts` (~line 383) → enqueue analysis
- `autoCloseExpiredShifts()` in `execution.service.ts` (~line 617) → enqueue analysis
- Missed-shift synthesis in `runExecutionMaintenance()` (~line 681) → deterministic absent analysis
- Sweep in `runExecutionMaintenance()`: concluded shifts with `kpiEvaluatedAt` but no `ShiftAnalysis` → enqueue (self-heals restarts/downtime)

**4. Env/deploy**: add `GEMINI_API_KEY` + `GEMINI_MODEL` to `workforce-backend/.env.example`, root `.env.production.example`, and the `workforce-backend` service `environment:` block in `docker-compose.prod.yml` (same as the avs-frontend service added in commit `6e20343`).

## Frontend (`workforce-frontend`)

**5. Sidebar** (`components/DashboardShell.tsx`): extend `NavItem["key"]` with `"link:ai-analysis"`; add "AI Analysis & Summary" (Sparkles icon, `href: /ai-analysis`) to the **admin** nav (near Execution Reports) and the **supervisor** nav.

**6. Chart building blocks**: `lib/charts.ts` (pure geometry: donut arcs, bar layout, pie wedges — shared math for screen and PDF) + small SVG components `components/charts/` (`ScoreDonut`, `BarChart`, `PieChart`) styled with existing CSS variables; types added to `types/workforce.ts`.

**7. Page `app/ai-analysis/page.tsx`** (modeled on `app/execution-report/page.tsx`): token from `localStorage`, role check admin ‖ supervisor via `/api/auth/me`.
- Filter panel: **worker** select → **concluded shift** select (defaults to most recent; shows analysis status), **"Report billed to"** hiring-manager select (supervisors from `/api/auth/users`, required before download — same pattern as invoice billed-to), Refresh + Generate/Regenerate button
- Metrics row: overall %, adherence, worked hours, punctuality, activity %, screenshots, plus a "Generated by Gemini · <time>" (or offline-fallback) badge
- Visualization area: big % score donut, bar chart (volume), pie chart (activity mix), narrative sections (headline, worker summary, work-done summary, highlights/concerns), screenshot evidence strip
- **Download PDF** disabled until an analysis + hiring manager are selected; fetches the last ~4 captures as data URIs via the existing authed `/api/monitoring/captures/:captureId/file` endpoint, then `pdf(<AIAnalysisPDF />).toBlob()` + anchor click

**8. `components/AIAnalysisPDF.tsx`** (modeled on `InvoicePDF.tsx` branding): teal/navy header band + logo, meta row (worker, shift date/time, billed-to manager with org name/address, analysis ref), donut score panel, KPI tiles, bar + pie charts drawn with `@react-pdf` SVG primitives from the shared geometry, narrative + highlights/concerns sections, screenshot evidence grid, footer (model, generated-at, page numbers). New page styles appended to `app/globals.css`.
